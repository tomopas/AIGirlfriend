# AI Girlfriend Bot

A personal AI girlfriend that runs entirely on your own machine. She chats with you on
Telegram, remembers things about you (including your preferences and kinks), texts you on
her own from time to time, and sends you photos generated by ComfyUI.

```
Telegram  <->  python bot (this repo)  <->  Ollama (LLM + memory embeddings)
                                          <->  ComfyUI (image/video generation)
```

This is a personal, single-user project. The "uncensored" behaviour comes from the local
model you choose and the `nsfw` setting — nothing is stored or processed off your machine
except the Telegram messages themselves. **Protect it**: the bot only talks to your own chat
id, but Telegram message senders are the owner of a token, so never expose the `.env` file.

## Prerequisites

- Python 3.10+ (tested on 3.14)
- [Ollama](https://ollama.com) running on `http://localhost:11434`
- [ComfyUI](https://github.com/comfyanonymous/ComfyUI) running on `http://localhost:8188`
  (start it with `--listen`) so the bot can reach its HTTP API
- A Telegram bot token from [@BotFather](https://t.me/BotFather)

## Setup

```bash
# 1. Python deps
pip install -r requirements.txt

# 2. Pull an uncensored model + an embedding model
ollama pull dolphin-llama3
ollama pull nomic-embed-text

# 3. Config
cp .env.example .env        # set TELEGRAM_BOT_TOKEN
cp config.example.yaml config.yaml
```

Find your Telegram chat id with [@userinfobot](https://t.me/userinfobot) and put it in
`.env` under `ALLOWED_CHAT_ID` (leave empty and the bot will refuse everyone — use `*` to
respond to any chat during testing only).

### ComfyUI workflow

1. In ComfyUI, build your txt2img graph and click **Save (API Format)** — this gives you the
   exact JSON the bot needs. UI-format exports will **not** work.
2. Save it to `workflows/image_workflow.json` and set `image_workflow` in `config.yaml`.
3. The bot finds and replaces the prompt text (all `CLIPTextEncode` positive nodes) and
   randomises all `KSampler` seeds automatically. Your checkpoint stays untouched.
4. For images you want to look anything like her, use a checkpoint that handles "realistic
   woman" prompt style well (e.g. Realistic Vision / SDXL-based) — the bot only passes
   prompts through; the checkpoint decides the look.

Video works the same way if you save a text2video workflow to `video_workflow`.

### Uncensoring an LLM with Heretic

If no ready-made uncensored model fits (or a new base model just dropped), you can
remove the refusal behaviour yourself with [Heretic](https://github.com/p-e-w/heretic)
(`pip install -U heretic-llm`). It performs *directional ablation* ("abliteration"):
it finds the model's internal "refusal direction" and orthogonalises it out of the
weights, while an Optuna-based search co-minimises refusal rate **and** KL divergence
from the original model — so the decensored model keeps its intelligence. No
fine-tuning, no transformer knowledge needed:

```bash
pip install -U heretic-llm
heretic Qwen/Qwen3-4B             # replace with any supported HF model id
```

Expect roughly 45 minutes for an 8B model on an RTX 3090. Heretic supports most dense
models, several MoE architectures, and some hybrids (Qwen3.5); pure state-space models
are not supported. Note the pipeline order: Heretic edits raw HuggingFace weights
(PyTorch/transformers) — Ollama can't run it directly. Convert the result to GGUF
(`llama.cpp`), then import it into Ollama with a `Modelfile` (`ollama create mymodel
-F Modelfile`) and set it as `LLM_MODEL` in `.env`.

Fast path if you have no GPU time: pull a community pre-abliterated model instead —
`huihui-ai/<model>-abliterated` variants or `*-heretic` GGUFs on the Ollama registry
are built exactly this way.

### NSFW image models (why stock Krea2-turbo says no)

NSFW success is decided by the **diffusion checkpoint**, not by prompt wording. Krea 2
ships open weights in two variants — RAW (52-step base) and Turbo (8-step distilled) —
but the stock `krea2_turbo_fp8_scaled` checkpoint is restriction-tuned: even explicit
prompts ("nude", "feet") come back as normal clothed selfies. Two things compound this:

1. The reference Krea workflow bakes a prompt-enhancer into the graph whose system
   prompt says *"assume clothing covers genitals"*. This bot neutralises that
   automatically (`ComfyClient.prepare(..., force=True)` replaces the linked prompt
   and prunes the enhancer chain before queueing), so you don't need to edit the
   workflow — but be aware of it if you test prompts by hand in ComfyUI.
2. A square *portrait* crop physically cannot show feet. The bot's prompt builder
   (`agf/persona.py`) therefore switches body-part subjects (feet, nude, lingerie)
   to full-body framing automatically — check the bot log (`image prompt (...)` line)
   to see the exact prompt that was queued.

If stock Turbo still refuses, swap the checkpoint — drop the file into
`ComfyUI/models/diffusion_models` (UNET-style, like Krea/Flux) or
`ComfyUI/models/checkpoints` (classic, like SDXL/Pony), point the loader node at it
in ComfyUI, **Save (API Format)**, and update `image_workflow` in `config.yaml`:

| checkpoint | type | notes |
|------------|------|-------|
| Uncensored Krea2 finetune (e.g. `Kreamania` on Civitai) | drop-in Turbo replacement | refined from Krea2 with the restrictions removed; keeps the same realism |
| `Pony Diffusion V6 XL` (+ NSFW merges) | classic checkpoint | the most-downloaded NSFW-capable family; needs an SDXL-style workflow, not the Krea graph |
| `IllustriousXL` (+ NSFW merges) | classic checkpoint | photorealistic SDXL fork with strong NSFW community support |

Residual refusals after a swap almost always come from the *text encoder*
(Qwen3VL on the Krea graph) rather than the checkpoint — rephrase rather than
pushing harder on the same words.

## Commands

| command              | what it does |
|----------------------|--------------|
| any text             | she replies; asking for a "photo/selfie/pic" triggers a ComfyUI generation |
| `/photo <prompt>`    | generate and send an image now |
| `/video <prompt>`    | generate via your video workflow (if configured) |
| `/remember <text>`   | store a fact manually |
| `/memories [page]`   | list stored memories (10 per page) |
| `/forget <id>\|profile\|all` | wipe one memory, tastes, or everything |
| `/clear`             | clear chat history |
| `/model`             | llm info |
| `/status`            | health of Ollama + ComfyUI |
| `/help`              | what she can do |

## How it works

- **Reply pipeline** — system prompt is built from `persona.yaml` + your remembered profile
  (kinks, preferences, private details). On top goes your recent chat history and the top-5
  relevant memories (embedding cosine similarity). Reply streams in and is saved to history.
- **Memory** — after every exchange a background pass asks the model to extract durable
  facts as JSON (`{fact, importance, kind}`). `pref` / `private` facts are promoted into the
  profile that is injected into her system prompt, so she *remembers* your sexual preferences
  and kinks. Everything lives in a local SQLite file (`data/memory.db`) with numpy stored
  embeddings.
- **Proactivity** — a background task wakes every N hours (configurable → default 2–6) and
  either sends you an in-character text or, with `proactive_image_prob` chance, a generated
  photo. `nsfw: true` lets those photos lean explicit (per `image_nsfw_tags`); `false` keeps
  her flirty but tasteful.

## Layout

```
main.py                 entry point
persona.yaml            who she is — edit freely
config.yaml             urls, models, intervals, nsfw switch
agf/
  config.py             env + yaml loading
  persona.py            system prompt / image prompt builders
  ollama_client.py      chat (streaming) + embeddings client
  comfy_client.py       workflow node discovery, queue, poll, download
  memory.py             SQLite + numpy memory store
  services.py           reply / photo / intent / memory-extraction pipeline
  telegram_bot.py       telegram handlers
  proactive.py          scheduling loop
workflows/              your API-format ComfyUI JSONs go here
tests/                  unit tests (config, memory, comfy, intent)
```

## Notes & caveats

- The uncensored personality only works if the **model itself** is uncensored; pick her
  brain accordingly and tune `temperature` in `config.yaml`.
- NSFW image quality is 100% determined by your ComfyUI checkpoint. If the checkpoint is
  poorly suited (e.g. vanilla SD1.5), "explicit" generations will just look tasteful.
- Media generated by ComfyUI is served over your local network only.
